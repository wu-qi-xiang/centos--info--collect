# P0 平台可靠性与事件行动项设计

## 目标

补齐运维平台自身的调度/通知可靠性可见性，并把事件复盘跟进事项从一段文本升级为可追踪的工作项。保留现有 Worker 队列告警、事件状态、审批、主机范围和审计行为。

## 方案

### 平台可靠性评估

复用 `ScheduledTaskRun` 和通知日志的安全聚合数据，新增只读服务/API 汇总：调度任务最后成功时间、当前状态、连续失败次数、通知渠道最近成功/失败计数和新鲜度状态。只保存任务名、渠道类型、状态、时间戳和计数，不保存 URL、消息、命令、告警原文或密钥。

评估只产生平台健康摘要和可选的内部告警，不触发重试、远程执行或通知发送。使用 DevOps 管理员权限访问；API 延续 `{ok, ...}` 响应格式。

### 事件行动项

新增 `IncidentActionItem`，关联事件，负责人绑定本地用户（允许为空表示待分派），包含标题、描述、状态、优先级、截止时间、完成时间、创建/更新时间和创建人。事件关闭不自动关闭行动项；所有创建、更新、完成、重新打开和删除均通过现有事件访问检查、模块权限和审计入口。列表仅返回授权事件的安全字段。

提供事件详情中的行动项列表与状态更新 API，逾期由查询计算，不新增后台副作用。现有 `Incident.follow_up` 保留用于兼容历史记录，新建复盘可将其作为初始描述但不再作为唯一跟踪载体。

## 验收

- 可靠性 API 能区分健康、过期、失败和无运行记录的调度/通知状态，并隐藏敏感字段。
- 行动项支持待分派、进行中、已完成、已取消，能记录截止和完成时间，越权访问返回现有错误格式。
- 现有 Worker、调度器、通知、事件、复盘和权限测试不回归；新增迁移可在 SQLite/PostgreSQL 兼容配置下执行。

## 风险与回滚

新增模型和 API 可独立迁移回滚；不改变现有模型字段语义，不改变远程执行和外部通知发送路径。若可靠性评估失败，只返回安全的不可用摘要，不阻塞现有调度任务。
