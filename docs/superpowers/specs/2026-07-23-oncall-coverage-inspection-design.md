# P5 服务值班覆盖巡检设计

## 目标

在告警发生前识别服务值班配置的覆盖风险，供安全管理员在现有服务值班页面中查看。

## 方案

巡检结果由服务层在读取时计算，不保存快照、不创建定时任务、不发送通知。检查范围是所有 `ServiceCatalog`：缺少或停用的策略、主值班或备值班通知渠道未启用、存在但没有可用成员的轮换名单，以及轮换位置不连续。

名单为空不是风险，因为现有轮换解析会使用静态主值班人。存在轮换成员但所有成员不可用时，仍会回退静态主值班人，但巡检会显示风险，提示管理员修复预期轮换。

## 权限与数据边界

页面继续复用服务值班页的 `security` 模块管理员权限。巡检仅返回服务名称、状态、风险代码和中文说明；不返回通知渠道 URL、渠道密钥或任何外部连通性结论。

## 验收

安全管理员能读取全部服务的覆盖风险清单；非管理员不能访问。完整、静态回退和异常轮换配置均有回归测试。巡检不修改 `ServiceOnCallPolicy`、轮换成员或通知记录。
