# 集成健康巡检设计

## 目标

将 Prometheus、Alertmanager 和已启用企业微信告警通知配置的可达性，作为脱敏的集成健康事件定期记录并展示给安全管理员。巡检不会修改远端配置、读取告警正文、发送企业微信消息、重试通知或触发远程执行。

## 方案

监控服务复用既有 Prometheus 与 Alertmanager 连接测试，按每个已启用且有地址的配置运行固定只读探测。Prometheus 使用既有状态端点，Alertmanager 使用既有 `/api/v2/status`；成功和固定的失败类型分别映射为 `ok`、`timeout`、`http_error`、`request_error` 或 `configuration`。

企业微信通知配置不使用 POST。巡检仅对已启用的企业微信 Webhook 发送 HEAD 请求：任意正常 HTTP 响应（含 405）表示传输链路可达；DNS、TLS、超时和连接失败记录为固定失败分类。它不验证机器人消息权限或凭据有效性；该验证继续使用人工“发送测试通知”操作。

DevOps 服务将每项结果通过现有 `IntegrationHealthEvent` 追加保存，只存来源编号、来源显示名、状态、固定分类和时间。健康 API 将监控通知巡检与既有 DevOps 通知投递汇总分开返回，不返回 URL、Webhook、响应头、响应正文、告警或密钥。

新增内置 `integration_health` 调度任务，使用环境变量控制间隔，默认 300 秒。单个配置失败不会阻塞其余配置或既有调度任务。

## 验收

- 调度运行后，每个可配置的 Prometheus、Alertmanager 和企业微信通知都有一条安全健康事件。
- 成功、超时、HTTP/TLS/DNS 失败映射到固定分类，不持久化异常文本或远端内容。
- 集成健康 API 仅限安全模块管理员，且返回字段不包含 URL、Webhook、Token、响应正文或消息内容。
- 企业微信巡检不调用 POST，不产生群消息。
- 既有调度、集成健康、监控及通知测试不回归。

## 风险与回滚

巡检新增外部网络请求，但使用现有短超时并隔离每个配置异常。设置较大的巡检间隔或移除调度注册即可停止新请求；保留历史事件不会影响告警、通知或远程执行的既有流程。
