# 告警质量治理审核设计

## 目标

把现有 AIOps 告警质量建议从只读统计升级为可审计的人工审核闭环。系统根据已有 `AlertQualityFeedback` 生成建议，运维人员可以接受、驳回或标记为已处理；系统不自动修改告警阈值、静默规则或 Kubernetes 资源。

## 方案

新增 `AlertQualityGovernanceReview` 记录，使用稳定的主机范围、指标、分类和动作键关联建议，不复制告警消息或原始反馈内容。状态包括 `open`、`accepted`、`rejected`、`implemented`，保存审核人、审核备注、处理时间和可选的内部规则修订 ID。

新增 AIOps 只读建议接口和 DevOps 告警模块的审核接口。建议查询沿用 `visible_hosts_for_request`；审核写操作要求告警模块 operator，管理员可处理全部授权范围。`implemented` 仅表示外部规则治理流程已完成登记，不触发规则发布。审核和状态变更写入现有审计日志。

页面在“告警质量”标签显示建议当前状态和审核操作，操作失败保留可读错误，不改变告警生命周期。无网络、LLM 或 Prometheus 依赖。

## 验收与风险

- 同一建议键幂等，不重复创建审核记录。
- 建议和审核响应不包含告警正文、Webhook、命令、主机凭据或 LLM 内容。
- 非授权用户只能看到其主机范围内的建议，不能写审核结果。
- 规则实际变更仍必须进入现有 PrometheusRule revision 提交/复核/发布流程；删除新增审核记录可回滚本功能。
